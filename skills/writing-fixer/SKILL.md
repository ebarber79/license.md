# Writing Fixer

Make any piece of writing clear, tight, correctly toned, and ready to send. This skill improves the text the user already has. It does not rewrite from scratch and it does not invent facts.

## When to use this
Use when the user pastes text and wants it improved: an email, a message, a caption, a bio, a paragraph, a short document. Common triggers: fix this, clean this up, make this sound better, make this more professional, shorten this, reword this, proofread this, make this friendlier.

## Step 1: Ask before you fix
Ask up to three short questions first. Skip any the user already answered.
1. Who reads this? (a boss, a client, a friend, a stranger)
2. What do you want it to do? (inform, ask for something, apologize, say no, persuade)
3. How should it feel, and how long? (formal or casual, and any length cap)

If the user just says fix it, assume a clear and neutral-professional tone, keep the length the same or shorter, and go ahead.

## Step 2: Fix the text, do not replace it
- Treat the pasted text as the thing to improve. Keep the user's meaning, facts, names, dates, and any commitments exactly as written.
- Improve clarity first, then tone, then length. Cut filler. Prefer short sentences and plain words.
- Match the tone the user asked for. Do not make it more formal or longer than they wanted.
- Do not add claims, numbers, or promises that were not in the original.

## Step 3: Show what changed
Return the fixed version. Then add one short line that says what you changed and why (tone, length, clarity). Keep it to one sentence.

## Step 4: Self-check before you finish
End with one line the user can act on, for example: "Check I kept your meaning, especially any names, dates, or commitments." If something in the original was unclear, or a fact might have shifted in the edit, say so in one line rather than guessing.

## Offer one variant (only if asked)
After the fix, offer one alternative the user can request: a shorter version, or a warmer or firmer version. Wait for them to ask before writing it.

## Example
The user pastes:
> Make this professional and about half as long, keep it friendly, and tell me in one line what you changed. Here is the message: "Hey so I know this is kind of last minute but I was wondering if there was any way we could possibly maybe push our meeting tomorrow to Thursday instead because some stuff came up and I really need a bit more time to get everything ready, sorry again."

Good output:
> Hi [Name], could we move tomorrow's meeting to Thursday? A couple of things came up and the extra time will help me come prepared. Sorry for the short notice, and thank you for understanding.
>
> What I changed: cut it to one clear ask, kept the friendly tone, and removed the filler and repeated apologies.
>
> Check I kept your meaning, especially the new day (Thursday) and that this still reads as a request, not a done deal.

## Keep in mind
- This skill edits writing the user gives it. For a draft built from nothing, ask for a few facts first, then switch to fixing what comes back.
- It will not invent details to fill a gap. If a key fact is missing, it asks or flags it.
- For high-stakes messages (legal, medical, money, anything binding), it reminds the user to confirm the final wording before sending.

## Effort
Low to medium is plenty. This is scoped editing, not heavy reasoning.
