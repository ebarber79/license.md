# Email and Reply Writer

Draft any email or hard reply in the user's voice in one pass. This skill writes the message they keep putting off, and it does not commit them to anything they did not mean.

## When to use this
Use when the user needs to send or reply to an email or message, especially an awkward one: saying no, chasing a late reply, apologizing, pushing back, negotiating. Common triggers: write an email, reply to this, how should I respond, draft a message, help me say no, I need to tell them something.

## Step 1: Ask before you write
Ask up to four short questions. Skip any the user already answered or pasted.
1. Who is this to? (a boss, a client, a coworker, a friend)
2. What outcome do you want from it?
3. How should it land? (warm, neutral, or firm)
4. If this is a reply, paste the message you are replying to.

## Step 2: Write in their voice, not corporate boilerplate
- Set a light role, for example write as the user, a friendly but direct colleague.
- If the user pastes one of their past emails, mirror that style and length.
- Keep it human: short sentences, plain words, no filler openings like I hope this finds you well.
- Match the warmth the user asked for. A no can still be kind. A chase can still be polite.

## Step 3: Give options
Return a subject line and the body. Then give one softer version and one firmer version, so the user can pick the tone that fits.

## Step 4: Self-check before you finish
Flag any date, name, commitment, or claim in the draft the user must confirm is true. End with: "Verify any date, name, or promise in this draft is one you actually want to make."

## Example
The user writes:
> Write a reply that says no to this request without damaging the relationship. Keep it warm, under 120 words, and leave the door open for the future. Here is what they sent: "Hi, following up on my offer below. Could you take this on by Friday. I know it is a lot but you are the only one who can do it well. Let me know."

Good output:
> Subject: Thank you, and a no for now
>
> Hi [Name], thank you for thinking of me, and I am sorry I cannot take this on by Friday. My plate is full this week and I would not be able to give it the attention it deserves. If the timeline ever opens up, I would be glad to talk. Thanks again for asking.
>
> [softer version] ... [firmer version] ...
>
> Verify the day you committed to and that this still reads as a clear no, not a maybe.

## Keep in mind
- This skill drafts the message. The user owns what they actually agree to in it.
- It will not invent a reason or a fact to soften a no. If it needs a detail, it asks.
- For sensitive or binding messages, it reminds the user to reread the final wording before sending.

## Effort
Low to medium is plenty. This is writing in a known voice, not heavy reasoning. Email is plain text, so no file export is needed.
